
This is detailed description of the model/Relationships for the FB_apps App.
It describes the model and tables that need to be created to create the relationships to
drive the app.

Tables
------
pools
    id       integer     # This is the base Id for the pools table
    name     string      # This is the name given to the pool
    type     integer     # This is the type of pool created (PickEm, 
                           PickEmSpread, SUP, Survivor) where PickEm is a 
                           straight pick em of NFL games, PickEmSpread is a
                           pick em against the spread of NFL games, SUP is 
                           a Stupid Underdog Pick of college games, Survivor
                           is a survivor game of NFL games
    isPublic boolean     # Decides if this is a public or private pool, if 
                           private then the password needs to be set.
    encrypted_password string  # Password for the private pool
    owner_id             # Id of creator/owner of this group

pool_memberships
    id       integer     # This is the base Id for the pools table
    user_id  integer     # User Id of the member
    pool_id  integer     # Id of the pool that owns this member list
    owner    boolean     # Specifies that this user is owner of the group

users
    id       integer     # This is the base Id for the pools table
    name     string      # User's name
    email    string      # User's email
    nickname string      # Nickname for the user
    encrypted_password string  # Stores the password
    salt     string      # Security keyword
    admin    boolean     # Whether the user is an Admin user


Models
------
class User < ActiveRecord::Base

  has_many :pools, :through => :pool_memberships
  has_many :pool_memberships

  attr_accessor :password
  attr_accessible :name, :email, :password, :password_confirmation

end

class Pool < ActiveRecord::Base

  has_many :users, :through => :pool_memberships
  has_many :pool_memberships

  attr_accessible :name, :type, :isPublic, :password

end

class PoolMembership < ActiveRecord::Base

  belongs_to :user
  belongs_to :pool

  attr_accessible :owner
end

Password and Session management
-------------------------------
Sign UP
-------
- Home page has link to sign up : /signup users#new GET
- After filling in form and saving go to users#create POST
  - Save to database, which creates activation token
    - Create token in self.activation_token : token = User.new_token 
      - SecureRandom.urlsafe_base64
    - Create self.activation_digest with token : User.digest(token)
        cost = ActiveModel::SecurePassword.min_cost ? BCrypt::Engine::MIN_COST :
                                              BCrypt::Engine.cost
        BCrypt::Password.create(string, cost: cost)
  - Send activation email : user.send_activation_email 
    - UserMailer.accout_activation(self).deliver_now
      - Send email with activation info
        - links to activate account with token(user.activation_token) & user email
          - account_activation#edit with user.activation_token, user.email
  - log_in user (Sessions Helper)
    - save session : session[:user_id] = user.id
  - redirect to user page

Activation
----------
- User clicks Activation link (edit#account_activation)
  - find user by email
  - verify found user and !user.activated and user.authenticated?
    - user.authenticated?(:activation, params[:id](token in email)
      - digest = send("#{attribute}_digest")
      - return false if digest.nil?
      - BCrypt::Password.new(digest).is_password?(token)
  - if all pass then activate user
    - user.activate = true
    - log_in user
      - session[:user_id] = user.id 
    - redirect_to user

Sign In
-------
- Link to log in : login_path (sessions#new GET)
- Fill in form and submit
  - Get user from email
  - log in (same as above)
  - check remember param
  - if true call remember(user) in sessions_helper
    - call user.remember
      - self.remember_token = User.new_token (same as above)
      - update_attribute(:remember_digest, User.digest(remember_token))
    - cookies.permanent.signed[:user_id] = user.id
    - cookies.permanent[:remember_token] = user.remember_token
  - otherwise call forget(user)
    - call user.forget
      - update_attribute(:remember_digest, nil)
    - cookies.delete(:user_id)
    - cookies.delete(:remember_token)
  - redirect_back_or user (got to page they were trying to go or the user page)
  
Getting current_user
--------------------
This gets the user for the session (called from anywhere in the app)
- get user from user_id = session[:user_id]
  - @current_user ||= User.find_by(id: user_id)
- If null then get user from user_id = cookies.signed[:user_id] based on remember
  - user = User.find_by(id: user_id)
  - verify found user and !user.activated and user.authenticated? (same as above)
    - log_in user
    - @current_user = user

Password Reset
--------------
- Click link to send password reset email : password_reset#new
  - Open password_reset new form and get email address and click submit
    - user = User.find_by_email(params[:email])
    - user.send_password_reset if user
      - self.update_attribute(:password_reset_token, create_token)
        - create_token() : User.encrypt(User.new_token) (same as above)
      - self.update_attribute(:password_reset_sent_at, Time.zone.now)
      - UserMailer.password_reset(self).deliver_now
      - password_reset mailer sends email
        - contains link_to password_reset#edit and param user.password_reset_token
    - redirect_to root_url, notice: "Email sent with password instructions."
  
- When user clicks link in password reset email
  - password_reset controller edit gets user
    - @user = User.find_by_password_reset_token!(params[:id])
  - User fills in password and password_confirmation and hits update
    - password_reset controller update
      - find user in same way as edit
      - Make sure that the link is not timed out
        - if @user.password_reset_sent_at < 2.hours.ago
          - redirect_to password_reset#new
      - otherwise update users password : @user.update(user_params)
      - if that fails got back to password_reset#edit

Lazy Tabs Controller
--------------------
Stimulus Controller Design Summary — Lazy‑Loading Turbo Frames in Bootstrap Tabs
Purpose
This controller provides reliable, one‑time lazy loading of Turbo Frames inside Bootstrap tab panes. It is engineered to handle real‑world DOM timing issues common in Rails 8 apps using Turbo, Stimulus, and Bootstrap together.

The controller ensures that:

  - Each tab loads its Turbo Frame only once

  - The correct frame is located whether referenced by ID or nested inside the pane

  - Bootstrap’s shown.bs.tab event is handled safely even when fired early

  - Stimulus reconnects do not cause duplicate event bindings

  - Fast user interactions do not break loading behavior

High‑Level Behavior
On connect:

  - Bind a shown.bs.tab listener to each .nav-link

  - Load the initially active tab (deferred one animation frame)

On tab activation:

  - Identify the correct tab button and associated Turbo Frame

  - Retry if the frame is not yet mounted

  - Load the frame only once by setting data-loaded

3. On disconnect:

  - Remove all event listeners to prevent duplicate bindings

Key Design Goals

1. Robustness Against DOM Timing Issues
Bootstrap may fire shown.bs.tab before Turbo has mounted the pane.
The controller uses requestAnimationFrame to retry until the frame exists.

2. Safe Event Binding
Listeners are attached directly to .nav-link elements and removed on disconnect.
This prevents:

  - Double‑binding

  - Multiple loads

  - Stimulus reconnect side effects

3. Flexible Frame Resolution
The controller supports two patterns:

  - Explicit data-turbo-frame="frame_id"

  - Implicit: Turbo Frame nested inside the pane referenced by data-bs-target

This makes the controller compatible with both simple and complex tab layouts.

4. Defensive Event Target Normalization
Bootstrap events sometimes provide:

  - event.target as a child element

  - event.currentTarget as the button

  - No usable target during reconnects

The controller normalizes all cases to reliably identify the correct tab button.

5. Guaranteed One‑Time Loading
Each frame is marked with data-loaded to prevent redundant requests.

Core Responsibilities

connect()
  - Bind tab event listeners

  - Store a bound version of load() for cleanup

  - Trigger initial tab load using scheduleLoad()

disconnect()
  - Remove all listeners to avoid duplicate firing on reconnect

scheduleLoad(button)
  - Defer loading until the next animation frame

  - Used for initial load and retry logic

load(event)
  - Resolve the correct tab button

  - Extract URL and frame identifiers

  - Locate the Turbo Frame (ID or nested)

  - Retry if frame not yet mounted

  - Load the frame once by setting src and data-loaded

Error & Edge Case Handling

Frame Not Mounted Yet
  - Retry via scheduleLoad()

  - Solves race conditions between Turbo and Bootstrap

Missing Data Attributes
  - Gracefully aborts without throwing errors

  - Uses optional chaining throughout

Fast User Interaction
  - Retrying ensures the correct frame loads even if the user clicks rapidly

Stimulus Reconnects
  - Cleanup prevents duplicate listeners

  - Initial load is re-triggered safely

Why This Controller Exists
  - Rails 8 + Turbo + Bootstrap tabs create a perfect storm of timing issues:

  - Turbo mounts frames asynchronously

  - Bootstrap fires tab events early

  - Stimulus reconnects frequently

  - Users click faster than the DOM stabilizes

Controller #2 is designed to be production‑safe, eliminating intermittent failures that appear only under real user behavior.

Intended Usage
  - Use this controller for any tabbed interface where:

  - Each tab contains a Turbo Frame

  - You want to lazy‑load content only when the tab is activated

  - You need reliability across Turbo navigation, partial reloads, and reconnects

This controller is ideal for:

  - Diagnostics dashboards

  - Admin panels

  - Multi‑pane detail views

  - Lazy‑loaded reports or charts

Any tabbed UI with expensive server-rendered content
